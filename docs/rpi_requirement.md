# rpi 宿主需求：BTW 旁路聊天视图

- 状态：已在独立宿主 worktree 实现并完成自动回归，真实终端交互验收待进行；尚未合并、发布或安装。
- 宿主实现：`D:/Projects/pi-rust-btw`，分支 `feat/btw-chat-view`；原宿主工作目录保持不动。
- 涉及项目：`rpi-package`（插件入口）、`pi-rust`（宿主与 TUI）
- 目标：让 `/btw` 具备完整 Markdown 展示、独立滚动、连续追问与生成中追加能力，同时保持主任务和主会话上下文隔离。

## 1. 背景与现状

以下“现状”为改动前基线。原 `rpi-btw` 只负责将 slash command 转发至宿主 `SideQuestion` runtime action（25），答案生成与面板展示由宿主管理。

已确认的问题：

| 问题 | 当前原因 |
| --- | --- |
| 没有 Markdown 渲染 | 答案通过通用 `UiComponent` 纯文本面板展示，未使用原生消息组件。 |
| 长答案显示不全 | `Job::publish` 按约 160 UTF-8 bytes 分行并截到 28 行，面板另有限制 `maxHeight: 18`，再次裁剪。 |
| 无法滚动 | 面板没有独立滚动状态、视口与滚轮路由。 |
| 无法连续追问 | 每次提问是独立请求，不保留旁路对话上下文；生成中再次提问直接报忙。 |

本需求不是简单调大面板高度，而是将被动文本预览升级为独立旁路聊天视图。

## 2. 参考与设计方向

参考第三方 Pi 扩展 `@narumitw/pi-btw`，本次分析查看的版本为 `0.61.2`：

- 使用原生 `UserMessageComponent` 和 `AssistantMessageComponent` 展示问答，复用 Markdown 与主题。
- 使用独立 `ScrollView` 承载完整旁路对话，而不是提前截断内容。
- 使用独立 `Editor` 接收追问，维护内存中的旁路线程与排队问题。
- 支持独立工作区及主、旁路分栏。

参考源码：<https://github.com/narumiruna/pi-extensions/tree/main/packages/pi-btw>

参考用于借鉴组件组合和交互模型，不要求复制其全部功能。该参考版本生成中主要展示加载状态；rpi 应保留自身已有的答案流式更新能力。

## 3. 目标与范围

### 3.1 本期必须实现

1. 使用原生消息组件渲染 Markdown。
2. 保留完整的可用答案，通过独立滚动视口访问，不再使用预览截断。
3. 提供旁路专用输入框，支持连续追问。
4. 生成过程中追加问题进入有上限的 FIFO 队列，不直接报忙。
5. 支持主任务与旁路任务同时运行，输入按焦点正确路由。
6. 默认右侧旁路、左侧主会话；窄屏时切换为旁路全屏视图。
7. 保持工具禁用、模型绑定继承、主上下文隔离和生命周期清理。

### 3.2 本期不要求

- 通用插件 `ui.custom()` ABI 或跨 DLL 的 Rust 组件传递。
- 任意插件自定义组件树协议。
- 可拖动分隔线、布局比例持久化、左侧旁路布局配置。
- 对话搜索、选区复制增强、Mermaid 专项支持。
- 旁路对话持久化、跨进程恢复。
- 自动把旁路答案写回主会话。

## 4. 架构与职责

### 4.1 新的渲染链路

当前：

```text
SideQuestion → 答案拼成字符串 → UiComponent 文本面板 → 截断展示
```

目标：

```text
SideQuestions 管理器
    ↓ 旁路状态快照 / 更新通知
SideQuestionView
    ├── 标题 / 运行状态
    ├── ScrollView
    │   ├── UserMessageComponent
    │   └── AssistantMessageComponent
    ├── 排队问题提示
    └── Editor
    ↓ 提问 / 取消 / 隐藏等交互事件
SideQuestions 管理器
```

### 4.2 职责边界

- **插件**：命令解析、调用 runtime action、返回简短操作反馈。
- **旁路管理器**：模型请求、旁路历史、队列、状态、取消、容量与生命周期管理。
- **旁路视图**：消息组件、Markdown、布局、滚动、输入框、焦点及交互展示。
- **宿主内部状态通道**：连接后台任务与 TUI，不暴露凭据，不写入主会话。

通用 `panels.rs` 继续服务统计信息等被动面板。BTW 不再依赖纯文本预览面板，不为本需求将 `UiComponent` 扩展成聊天系统。

## 5. 功能需求

### 5.1 Markdown 与流式展示

- 问题使用 `UserMessageComponent`，回答使用 `AssistantMessageComponent`。
- 复用 `rpi-tui` 的现有 Markdown 渲染、主题与代码块样式，不另写解析器。
- 按分配给当前窗格的实际宽度渲染，正确处理中文、长文本、列表和代码块。
- 流式生成期间更新当前回答，生成结束后在同一条回答上收敛为最终状态，不重复追加完整答案。
- 删除当前 160-byte 分行与 28 行截断逻辑，不用扩大静态面板高度代替滚动。
- 内容安全上限仍然生效。输出超限须明确显示错误，不可静默截断后伪装为完整回答。
- 在渲染边界处理不可信终端控制序列，复用原生组件的安全策略。

### 5.2 滚动

- 每个可见旁路视图拥有独立 `ScrollView`，不复用主会话的滚动偏移。
- 完整消息内容保留在状态中，只有视口显示部分被裁剪。
- 标题、状态提示和输入框位于正文滚动区域之外。
- 用户在底部时，新输出可跟随末尾。
- 用户向上浏览时，新输出不得强制拉回底部，也不得因为临时内容适配而自动恢复跟随。
- 终端 resize 或分栏宽度变化后重新排版，并校正偏移，确保首行、末行均可到达。
- 支持 `PageUp` / `PageDown`；旁路获得焦点时只滚动旁路正文。
- 鼠标位于旁路区域时，滚轮只滚动旁路；位于主会话区域时仍滚动主会话。滚轮不必改变键盘焦点。
- 提供返回最新内容的操作或清晰提示。

### 5.3 旁路线程与追问

现有一次性 `Job` 需要增加线程层。下列结构仅为设计示意，不是现有 API，也不要求照抄字段：

```rust
struct SideThread {
    turns: Vec<SideTurn>,
    pending: VecDeque<String>,
    active: Option<ActiveRequest>,
    visible: bool,
}
```

行为要求：

- 同一 owner、同一主会话内维护独立旁路线程。
- `/btw <问题>` 在有现存旁路线程时延续对话；没有时创建线程。
- 旁路输入框中提交的问题使用同一语义，不需要绕回插件 DLL 执行 slash command。
- 后续请求带上之前成功完成的旁路问答，以正确的用户/助手角色组织历史。
- 失败或取消的部分答案可以保留展示，但不得作为成功完成的助手回答加入后续模型上下文。
- 生成中提交的问题进入有限 FIFO 队列，界面和命令反馈明确显示排队状态。
- 同一旁路线程串行调用 provider；当前请求真正结束、完成必要清理后再启动下一条。
- 历史仅保存在内存，按完整问答轮进行有界保留；发生裁剪时明确告知，不静默丢失上下文。

建议首期边界：

| 项目 | 限制 |
| --- | --- |
| 单个问题 | 保留 1–20,000 UTF-8 bytes 限制 |
| 待执行问题队列 | 最多 8 条；超限时明确拒绝新增，不丢弃已接受问题 |
| 单次回答 | 保留 256 KiB 上限 |
| 单次文本增量 | 保留最多 8192 个增量 |
| 单次请求超时 | 保留默认 120 秒 |
| 已完成历史 | 最多 16 轮且问答文本合计不超过 1 MiB；超出时移除最旧完整轮 |

历史统计包含问题和答案文本；展示与后续上下文使用一致的已保留问答集合，不无限累积旧消息组件或重复的模型响应副本。

### 5.4 输入、焦点与布局

输入路由要求：

| 交互 | 行为 |
| --- | --- |
| 打开 BTW | 展示旁路视图并将焦点交给旁路输入框，主任务继续运行。 |
| 旁路输入框 Enter | 提交旁路问题；运行中则排队。 |
| 旁路获得焦点时 PageUp/PageDown | 滚动旁路正文，不移动主会话视口。 |
| 鼠标滚轮 | 滚动指针所在区域，不强制切换键盘焦点。 |
| 点击主会话输入区域 | 切回主输入框，后续普通输入仍进入主任务。 |
| 点击旁路输入区域 | 切回旁路输入框。 |
| Esc 关闭旁路视图 | 隐藏视图、恢复主输入焦点，不自动取消生成。 |
| 旁路获得焦点时 Ctrl+C | 取消当前旁路生成并清空待执行队列，不取消主任务；保留已完成问答。 |

- 使用两个独立编辑状态，切换视图不得覆盖或丢失主输入草稿。
- 默认右侧旁路、左侧主会话；主窗格继续复用原有主会话渲染，不复制 transcript 到旁路。
- 宽屏时两个窗格均保持更新；输入只路由给当前有焦点的区域。
- 建议终端宽度低于 100 列时退化为旁路全屏，避免两个窗格均过窄；恢复宽度后返回分栏。全屏退化不得丢失草稿、历史或滚动状态。
- 遵守现有全局退出、模态对话与权限审批的优先级；旁路不得拦截并绕过必须处理的宿主交互。
- Alt-screen 模式先实现分栏；regular/native scrollback 模式使用旁路全屏交互，并在退出时恢复原主界面，不将临时旁路 UI 写成主会话消息。

### 5.5 显示与生命周期

- 隐藏视图不取消任务；再次显示可从状态重建完整的已保留对话。
- `/btw cancel` 取消当前生成并清空待执行队列，保留已完成问答。
- 新话题操作取消旧线程及其队列，丢弃旧历史后创建新线程。
- 清理操作取消线程、清空历史和队列，并移除视图。
- 会话切换、会话关闭、扩展卸载/reload 时取消请求并清理对应 owner 的线程和 UI。
- 迟到的 provider 增量或终态不得复活已关闭线程、覆盖新话题，或写入另一会话的视图。线程与请求均需稳定身份用于验证归属。
- 取消不等于强杀 provider。后台驱动真正退出前仍占用相应容量；排队问题不能绕过现有容量限制。

### 5.6 隔离与模型配置

- 旁路问题、答案和 UI 操作默认不写入主 transcript。
- 不使用主会话的 `SendMessage`、`AppendEntry` 或 steering/follow-up 队列承载旁路追问。
- 继续使用宿主管理的工具禁用请求，禁止旁路检查文件、编辑代码或执行工具。
- 每轮执行继承提交时宿主生效的模型、provider 私有绑定和 thinking 配置；排队项目需保留提交时配置快照，不能在等待期间静默换模型。
- 主会话参考片段继续仅来自已提交用户/助手文本，不复制未完成流式内容、工具结果、图片、thinking 或自定义元数据。
- 新旁路线程固定其初始主会话参考片段，后续追问默认基于该参考片段与旁路历史，不暗中持续注入主任务新内容。
- API key、认证头、endpoint 与内部 runtime handle 不输出给插件命令结果或模型文本。
- 不启动第二个 `rpi` 子进程，不重新读取默认配置作为模型回退路径。

## 6. 宿主内部状态通道

现有 `SideQuestionSink` 主要用于更新通用面板，应调整为旁路管理器与交互视图解耦的状态通知机制；具体类型可复用宿主现有 mailbox/watch 模式。

要求：

1. 后台生成任务更新旁路状态，发布快照或版本通知，不直接操作 TUI 组件。
2. TUI 按稳定的 owner / 主会话 / 线程 / 请求身份读取状态，并处理增量更新。
3. TUI 的提问、取消、显示和隐藏事件进入宿主管理器，由异步执行路径处理，不在输入线程阻塞等待模型。
4. 请求结束后仍可读取已完成历史；隐藏后可恢复，移除后不可被旧通知复活。
5. 无交互 UI 时，不创建 TUI 视图；`/btw status` 仍可返回状态和完整的当前可用答案。
6. 并发操作不得导致重复提交、队列乱序、取消后自动启动下一条或旧任务覆盖新线程。

## 7. 插件协议与命令

继续使用 `RuntimeActionId::SideQuestion`（25）。本期无需新增通用自定义 UI ABI，也不更改 C ABI vtable 布局或 SDK pin。

| 命令 | 目标行为 |
| --- | --- |
| `/btw` | 打开或恢复旁路视图；没有线程时显示空的旁路输入框。 |
| `/btw <问题>` | 创建或延续旁路线程；生成中则排队。 |
| `/btw status` | 返回当前状态、队列数量和完整当前可用答案；可附带历史保留信息。 |
| `/btw cancel` | 取消当前旁路请求及待执行队列，保留已完成历史。 |
| `/btw hide` | 隐藏视图，不取消任务。 |
| `/btw show` | 恢复视图；没有线程时显示空输入框。 |
| `/btw new <问题>` | 取消并清理旧线程，开始新话题。 |
| `/btw clear` | 取消并清空旁路线程、历史、队列与视图。 |
| `/btw help` | 展示命令与交互帮助。 |

- 以上是目标协议，新增操作须由宿主验证和实现，不能仅在插件中改文案。
- 插件返回值需区分 `started`、`queued` 与失败，不得对排队请求谎称已经开始生成。
- 仅精确匹配保留子命令；`new` 只有带后续问题时按新话题语法处理，缺少问题时返回用法提示。
- 旧宿主不支持相关操作时明确提示升级，不静默降级为无历史或换模型的请求。
- 更新插件 README，删除“仅预览、运行中报忙、不累计旁路上下文”的旧说明。

## 9. 验收标准

### 9.1 展示与滚动

- 超过 28 行的长回答不再被预览截断，滚动可到达首行和最后一行。
- 标题、粗体、列表、中文与代码块使用原生 Markdown 样式正常展示。
- 流式回答更新与最终回答不重复，不破坏正在浏览的历史位置。
- 鼠标滚轮与 PageUp/PageDown 操作正确的窗格，不意外滚动主会话。
- 终端缩放、窄屏退化、恢复分栏后，内容仍可完整访问且输入草稿不丢失。

### 9.2 追问与队列

- 第二次追问的模型输入包含之前成功完成的旁路问答。
- 生成中追加多条问题时，UI 显示队列并按 FIFO 串行执行。
- 队列达到上限时明确拒绝新增，已接受的问题不丢失。
- cancel 后清空待执行队列，不再自动发起下一条。
- new/clear、会话切换及插件卸载后，旧增量不能污染新视图。
- 历史达到上限时按完整轮裁剪，并有明确提示。

### 9.3 隔离与回归

- 旁路打开、追问、取消、隐藏均不改变主会话 transcript、主任务队列和工具集合。
- 主任务生成期间旁路仍可使用，旁路取消不会取消主任务。
- 主输入与旁路输入分别保留草稿；焦点切换不误投问题。
- 不同 owner、不同主会话的旁路历史、队列与视图不串用。
- 原有输出限制、超时、执行容量、provider 清理和旧宿主错误测试继续通过。
- 通用被动面板、主 transcript 滚动、权限审批与其他模态交互不受回归影响。

## 10. 建议验证方式

- 插件单测：精确命令解析、UTF-8 限制、started/queued 反馈、兼容错误与 owner handle。
- 宿主状态测试：连续追问、FIFO、取消/清空、新话题、历史裁剪及 session/owner 隔离。
- TUI 组件测试：长 Markdown、中文宽度、滚动首尾、手动浏览后的流式更新、resize 与焦点路由。
- 保留并扩展真实动态库集成测试，设置 `RPI_TEST_BTW_LIBRARY` 后运行 `btw_package`。
- 实际终端验证宽屏分栏与窄屏全屏、滚轮、连续输入、主任务并行与退出后草稿恢复。
