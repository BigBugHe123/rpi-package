# 当前改动继续审查：模型设置与压缩结算

基线发布：`rpc-20261021-105322`。范围为 pi-rust 原生 RPC、压缩操作，以及 rpi-web 当前改动中的模型、思考深度、工具设置和会话切换。以下结论针对已检查范围，不代表软件不存在未知缺陷。

## 确认并修复的问题

| 优先级 | 问题 | 修复及回归依据 |
| --- | --- | --- |
| P2 | 不同服务商使用相同模型 ID 时，选择第二个模型会发送第一个服务商；斜杠命令也会任意选择重名模型。 | 下拉值、React key 和上下文查找使用 provider + id；斜杠命令支持 provider/id，对含糊匹配明确拒绝。浏览器先复现错误服务商，修复后检查请求和上下文窗口。 |
| P2 | 切换会话后，前一个会话延迟返回的工具设置会覆盖当前工具目录。 | 会话修订号和存活检查保护结果的所有状态修改，工具目录只在当前请求仍有效时更新。持有旧响应、创建新会话、再返回旧响应的浏览器回归通过。 |
| P2 | 模型切换后仍显示旧思考选项，设置结果还可能显示请求值而非原生实际值。 | 修改完成后读取原生状态；模型或服务商改变时重新加载目录，加载期间禁用旧选项。回归覆盖原生将 high 归一化为 low，以及新模型仅支持 off 的延迟响应。 |
| P2 | 手动压缩的 RPC 结算缺少 runId，不能与持久化操作可靠关联。 | 所有压缩结果增加 runId；原生 RPC 测试核对结算 ID 和操作完成记录。修复前回归失败，修复后通过。 |
| P2 | 无需压缩时已经写入 operation_started，却没有 operation_finished，留下虚假的未结束操作。 | Declined 分支写入唯一的 Declined 完成记录并传播写入错误。Harness 回归、真实原生 RPC 和桥接快照均核实没有 openOperations，且没有调用模型。 |
| P3 | 移动端侧栏切换按钮与工作区按钮使用相同名称，操作语义不清，严格定位不唯一。 | 使用独立的中英文“切换侧栏”动作名称，移动端回归使用该可访问名称。 |
